# stm32-uart-dma

[![CI](https://github.com/M100ika/stm32-uart-dma/actions/workflows/ci.yml/badge.svg)](https://github.com/M100ika/stm32-uart-dma/actions/workflows/ci.yml)

Прошивка для STM32F401RE и STM32F446RE (платы Nucleo-64) без HAL и без CMSIS.
Всё написано на регистрах: таблица векторов, стартовый код, линкер-скрипт,
тактирование от PLL, драйвер USART2 с приёмом и передачей через DMA,
прерывания, сторожевой таймер и сохранение отчёта о HardFault между перезагрузками.

Поверх драйвера работает командная строка на виртуальном COM-порту ST-LINK.

```
stm32-uart-dma 1.0.0 (STM32F401RE)
reset cause: power-on
type help for commands
> stats
rx bytes:      6
tx bytes:      214
...
```

## Возможности

- **Свой стартовый код.** Таблица векторов на C, `Reset_Handler` включает FPU,
  копирует `.data`, обнуляет `.bss`. Линкер-скрипт проверяет, что под стек остаётся
  не меньше 4 КБ.
- **Тактирование.** HSI 16 МГц → PLL → 84 МГц, APB1 42 МГц, задержки флеша
  выставляются до повышения частоты. Если PLL не запустилась, прошивка
  продолжает работать на HSI и сообщает об этом.
- **UART через DMA в обе стороны.** Приём: циклический DMA и прерывания по половине
  буфера, концу буфера и паузе на линии (IDLE). Передача: кольцевой буфер и DMA
  на непрерывные куски. Процессор получает одно прерывание на пачку байт, а не на каждый байт.
- **Кольцевой буфер без блокировок** для пары «прерывание ↔ основной цикл»
  с атомарными индексами (acquire/release).
- **Диагностика.** Причина сброса из `RCC_CSR`. Отчёт о HardFault (PC, LR, CFSR,
  HFSR, адреса сбоя) сохраняется в неинициализируемой области ОЗУ и выводится
  после перезагрузки. Независимый сторожевой таймер IWDG.
- **Кнопка на внешнем прерывании** (EXTI) с подавлением дребезга.
- **Энергосбережение.** Основной цикл засыпает в `WFI` до следующего прерывания.
- **Тесты на ПК.** Логика, не зависящая от железа (кольцевой буфер, учёт DMA-позиции,
  командная строка, форматирование чисел), покрыта unit-тестами. Тесты прогоняются
  с AddressSanitizer, UndefinedBehaviorSanitizer и ThreadSanitizer.
- **CI** на GitHub Actions: сборка под обе платы, тесты, cppcheck.

## Аппаратная часть

| Сигнал | Вывод | На плате |
|---|---|---|
| USART2 TX | PA2 (AF7) | виртуальный COM-порт ST-LINK |
| USART2 RX | PA3 (AF7) | виртуальный COM-порт ST-LINK |
| LD2 | PA5 | зелёный светодиод |
| B1 | PC13 | синяя кнопка, активный уровень низкий |

Дополнительных проводов не нужно: достаточно подключить Nucleo по USB.

## Сборка и прошивка

Нужны `arm-none-eabi-gcc` (≥ 10) и `make`, для прошивки — `st-flash` из пакета stlink-tools.

```bash
make                  # STM32F401RE -> build/F401RE/firmware.{elf,bin,hex}
make MCU=F446RE       # STM32F446RE
make flash            # прошить по ST-LINK
make test             # unit-тесты на ПК (ASan + UBSan)
make test-tsan        # те же тесты с ThreadSanitizer
```

Вместо `make flash` можно просто перетащить `firmware.bin` на USB-диск NODE_F401RE / NODE_F446RE.

Терминал: 115200 бод, 8N1, например `picocom -b 115200 /dev/ttyACM0` или PuTTY.

## Команды

| Команда | Что делает |
|---|---|
| `help` | список команд |
| `led on\|off\|toggle\|auto` | управление светодиодом, `auto` — мигание |
| `uptime` | время с запуска |
| `stats` | счётчики UART и DMA: принято, отправлено, потеряно, ошибки линии |
| `echo <текст>` | вернуть текст |
| `info` | версия, ID кристалла, частоты |
| `reset` | программный сброс |
| `fault` | вызвать HardFault; после перезагрузки выводится отчёт |
| `hang` | остановить основной цикл; через ~2 с сработает сторожевой таймер |

## Устройство

Приём (в прерываниях → основной цикл):
```
PA3 ─▶ USART2 ─▶ DMA1 Stream5 ─▶ rx_dma[64] ─▶ rx_tracker ─▶ rx_rb[512] ─▶ uart_read ─▶ cli_feed
                  (циклический)   события HT, TC, IDLE        SPSC-буфер     основной цикл
```

Передача (основной цикл → прерывание TC):
```
команды ─▶ uart_puts ─▶ tx_rb[1024] ─▶ кусок до конца массива ─▶ DMA1 Stream6 ─▶ USART2 ─▶ PA2
                        SPSC-буфер     TC: rb_skip, следующий кусок
```

| Модуль | Назначение | Тесты на ПК |
|---|---|---|
| `startup.c`, `ld/*.ld` | таблица векторов, Reset_Handler, карта памяти | — |
| `regs.h`, `cpu.h` | регистры, критические секции, NVIC | проверки `_Static_assert` |
| `clock.c` | PLL, задержки флеша, делители шин | — |
| `systick.c` | миллисекундный таймер | — |
| `board.c` | GPIO, светодиод, кнопка на EXTI | — |
| `uart_dma.c` | драйвер USART2 + DMA | — |
| `diag.c` | причина сброса, HardFault, IWDG | — |
| `ringbuf.c` | SPSC-буфер без блокировок | да, включая многопоточный |
| `rx_tracker.c` | новые байты в циклическом DMA-буфере | да |
| `cli.c` | разбор командной строки | да |
| `strutil.c` | числа в строку без printf | да |

### Приоритеты прерываний

| Источник | Приоритет | Почему |
|---|---|---|
| SysTick | 4 | время не должно отставать из-за других обработчиков |
| DMA1 Stream5 (RX), USART2 | 5 | одинаковый приоритет: не вытесняют друг друга, общий код приёма не нужно защищать от повторного входа |
| DMA1 Stream6 (TX) | 6 | передача терпит задержку, приём — нет |
| EXTI15_10 (кнопка) | 7 | человеку не важны микросекунды |

### Память

Флеш около 7,7 КБ, ОЗУ около 5,9 КБ (из них 4 КБ — гарантированный запас под стек).
Кучи нет: `malloc` и `printf` не используются.

## Ограничения

- Конфигурация одна для обеих плат (84 МГц). F446 может работать на 180 МГц,
  но для этого нужны режим Over-Drive и другие задержки флеша.
- Если между двумя проверками придёт больше 64 байт, часть данных потеряется
  незаметно. На 115200 бод полбуфера приходит за 2,8 мс, а прерывания HT/TC
  гарантируют проверку не реже, чем раз в полбуфера.
- Регистры описаны вручную ради наглядности; в рабочем проекте лучше брать
  CMSIS-заголовки производителя.
