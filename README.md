# stm32-uart-dma — модуль ввода-вывода Modbus RTU на STM32 без HAL

[![CI](https://github.com/M100ika/stm32-uart-dma/actions/workflows/ci.yml/badge.svg)](https://github.com/M100ika/stm32-uart-dma/actions/workflows/ci.yml)

Устройство, через которое контроллер верхнего уровня (ПЛК, SCADA, Raspberry Pi
или ПК) читает показания и управляет выходом **через регистры по протоколу
Modbus RTU** — стандарту промышленной автоматики. Прошивка для
STM32F401RE / STM32F446RE (платы Nucleo-64) написана на регистрах:
без HAL, без CMSIS, со своим стартовым кодом и линкер-скриптом.
UART работает через DMA в обе стороны, отсюда название репозитория.

## Где применяется

Типичная схема на объекте: один мастер и несколько таких модулей на общей
шине RS-485 длиной до километра (до 32 устройств на сегмент, с приёмопередатчиками
на 1/8 нагрузки — больше; адресов в протоколе 247). Например, на ферме шлюз
на Raspberry Pi опрашивает модули у весов, кормушек и вентиляции: снимает показания,
включает исполнительные механизмы и следит, не перезагружался ли модуль и нет ли
ошибок на линии.

```
 Raspberry Pi / ПЛК / SCADA          шина RS-485 (A/B), 115200 8N1
 ┌────────────────────┐     ┌────────────────┬────────────────┬─────
 │  Modbus RTU master ├─────┤    модуль 1    │    модуль 2    │ ...
 └────────────────────┘     │ STM32 + MAX485 │ STM32 + MAX485 │
                            └────────────────┴────────────────┘
```

Для проверки дополнительное железо не нужно: на Nucleo линия USART2 выведена на
виртуальный COM-порт ST-LINK, так что мастером служит ПК, подключённый по USB.

## Карта регистров

Адреса — смещения от нуля (в документации SCADA их часто пишут как 00001, 10001, 30001, 40001).

**Coils** — биты, чтение и запись (функции 0x01, 0x05)

| Адрес | Назначение |
|---|---|
| 0 | выход включён: 1 — уровень 100 %, 0 — выключен |
| 1 | режим мигания |

**Discrete inputs** — биты, только чтение (0x02)

| Адрес | Назначение |
|---|---|
| 0 | кнопка нажата сейчас |

**Input registers** — только чтение (0x04)

| Адрес | Назначение | Единицы |
|---|---|---|
| 0 | код кристалла | 0x0433 — F401, 0x0421 — F446 |
| 1 | версия прошивки | 0x0200 = 2.0 |
| 2, 3 | время работы, старшее и младшее слово | с |
| 4 | число нажатий кнопки | |
| 5 | температура кристалла | 0,1 °C, со знаком |
| 6 | напряжение питания VDDA | мВ |
| 7 | причина последнего сброса | 1 питание, 2 кнопка RESET, 3 программный, 4 сторожевой таймер |
| 8, 9 | адрес HardFault в прошлом запуске | 0 — сбоя не было |
| 10 | обработано кадров | по модулю 65536 |
| 11 | ошибок CRC | |
| 12 | отправлено исключений | |
| 13 | ошибок линии UART (переполнение, кадр, шум, DMA) | |
| 14 | потеряно принятых байт | |

**Holding registers** — чтение и запись (0x03, 0x06, 0x10)

| Адрес | Назначение | Допустимо |
|---|---|---|
| 0 | уровень ШИМ-выхода | 0..1000 ‰ |
| 1 | режим: 0 — постоянно, 1 — мигание | 0, 1 |
| 2 | полупериод мигания | 50..10000 мс |
| 3 | команда: 0xA5A5 — сброс, 0xDEAD — проверка HardFault, 0x5741 — проверка сторожевого таймера | только эти коды |
| 4..11 | 8 регистров для данных мастера | любые |

Недопустимое значение возвращает исключение 03, адрес вне таблицы — 02,
неподдерживаемая функция — 01. Запись нескольких регистров (0x10)
применяется целиком или не меняет ничего. Широковещательная запись
(адрес 0) выполняется без ответа.

ШИМ-выход на Nucleo управляет светодиодом LD2; на реальном модуле это мог бы быть
клапан, вентилятор или нагреватель через транзисторный ключ.

## Быстрая проверка

```bash
make flash                                         # прошить Nucleo-F401RE
pip install -r tools/requirements.txt
python3 tools/modbus_module.py --port /dev/ttyACM0 status
python3 tools/modbus_module.py --port /dev/ttyACM0 level 100      # 10 % яркости
python3 tools/modbus_module.py --port /dev/ttyACM0 blink off
python3 tools/modbus_module.py --port /dev/ttyACM0 watch          # показания раз в 0,5 с
```

В Windows порт будет `COM5` или похожий. Подойдёт и любой другой мастер:
QModMaster, Modbus Poll, `pymodbus`, ПЛК. Параметры: адрес 1, 115200, 8N1.

## Подключение RS-485

| Nucleo | Модуль MAX485 / SP3485 |
|---|---|
| PA2 (D1, USART2 TX) | DI |
| PA3 (D0, USART2 RX) | RO |
| PA8 (D7) | DE и /RE, соединённые вместе |
| 3V3, GND | VCC, GND |

По умолчанию PA2/PA3 подключены к ST-LINK, а не к разъёму. Чтобы вывести
USART2 на D0/D1, на Nucleo-64 нужно разомкнуть перемычки SB13, SB14
и замкнуть SB62, SB63 (UM1724, раздел про USART). Тогда связь через USB
пропадёт — мастер подключается к шине RS-485.

## Как устроена прошивка

```
приём:    PA3 ─▶ USART2 ─▶ DMA1 S5 (циклический) ─▶ rx_tracker ─▶ кольцевой буфер ─┐
                            события HT, TC, IDLE + отметка времени TIM5             │
                                                                                    ▼
основной цикл:  mb_rtu (пауза t3.5 = 1,75 мс) ─▶ mb_process ─▶ карта регистров app
                                                     │                     │
передача: PA2 ◀─ USART2 ◀─ DMA1 S6 ◀─ кольцевой буфер ◀┘     ШИМ TIM2, АЦП, кнопка
          PA8 (DE) поднимается перед передачей, опускается по флагу TC у USART
```

| Модуль | Назначение | Тесты на ПК |
|---|---|---|
| `startup.c`, `ld/*.ld` | таблица векторов, Reset_Handler, карта памяти | — |
| `regs.h`, `cpu.h` | регистры, критические секции, NVIC | `_Static_assert` на смещения |
| `clock.c` | PLL 84 МГц, задержки флеша, делители шин | — |
| `uart_dma.c` | USART2 + DMA в обе стороны, RS-485 DE | — |
| `ringbuf.c` | SPSC-буфер без блокировок | да, включая многопоточный + TSan |
| `rx_tracker.c` | новые байты в циклическом DMA-буфере | да |
| `mb_rtu.c` | разбиение потока на кадры по паузам | да |
| `modbus.c` | CRC, функции, исключения, broadcast | да |
| `app.c` | карта регистров и логика выхода | да |
| `sensor_calc.c` | АЦП → мВ и °C по заводской калибровке | да |
| `adc.c`, `pwm.c`, `timer_us.c` | АЦП, ШИМ TIM2, микросекунды TIM5 | — |
| `board.c`, `systick.c`, `diag.c` | кнопка на EXTI, 1 мс, сбросы, HardFault, IWDG | — |

### Приоритеты прерываний

| Источник | Приоритет | Почему |
|---|---|---|
| SysTick | 4 | время не должно отставать |
| DMA1 Stream5 (RX), USART2 | 5 | одинаковый приоритет: не вытесняют друг друга, приёму не нужна защита от повторного входа |
| DMA1 Stream6 (TX) | 6 | передача терпит задержку, приём — нет |
| EXTI15_10 (кнопка) | 7 | человеку не важны микросекунды |

### Надёжность

- **Сторожевой таймер IWDG** (~2 с) перезагрузит модуль, если основной цикл зависнет.
- **Отчёт о HardFault** (PC, LR, CFSR, HFSR) сохраняется в `.noinit`, и после
  перезагрузки мастер может его прочитать (регистры 8–9).
- **Причина сброса** из `RCC_CSR` доступна в регистре 7.
- Если PLL не запустится, модуль продолжит работу на HSI 16 МГц, а скорость UART
  останется верной, потому что делитель считается по фактической частоте.

### Память

Флеш около 7,6 КБ, ОЗУ около 6 КБ (из них 4 КБ — гарантированный запас под стек).
Нет кучи, `malloc` и `printf`.

## Сборка и тесты

```bash
make                  # STM32F401RE -> build/F401RE/firmware.{elf,bin,hex}
make MCU=F446RE       # STM32F446RE
make flash            # прошить по ST-LINK (st-flash)
make test             # unit-тесты на ПК: ASan + UBSan
make test-tsan        # те же тесты с ThreadSanitizer
make interop          # симулятор модуля + независимый мастер minimalmodbus
```

`make interop` собирает на ПК симулятор из тех же файлов протокола и карты
регистров, что и прошивка, и гоняет через псевдотерминал запросы всех функций
от сторонней библиотеки. Это проверяет совместимость с чужой реализацией Modbus,
а не только с собственными тестами.

CI на GitHub Actions собирает прошивку под обе платы, запускает тесты,
cppcheck и проверку совместимости.

## Ограничения

- Адрес модуля и скорость задаются при сборке (`make MB_ADDR=5 MB_BAUD=19200`);
  хранение настроек во флеше — следующий шаг.
- Нарушение паузы t1.5 внутри кадра не отслеживается: такие кадры отсеиваются
  проверкой CRC.
- Одна конфигурация тактирования для обеих плат (84 МГц).
- Регистры описаны вручную ради наглядности; в рабочем проекте лучше брать
  CMSIS-заголовки производителя.
